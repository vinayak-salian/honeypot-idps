
# 🛡️ Nexus Security Core

## AI-Enhanced Distributed Honeypot & Intrusion Detection Platform

Nexus Security Core is a hybrid cybersecurity platform designed to detect, analyze, and respond to malicious activities across both public-facing cloud infrastructure and private local networks. The project combines deception technologies (honeypots), machine-learning-assisted intrusion detection, centralized telemetry, and automated mitigation into a unified Security Operations Center (SOC) dashboard.
 
The platform consists of two independent security sensors:

* **Cloud Threat Sources** – Internet-facing AWS honeypots that capture real-world attacks.
* **Local Threat Sources** – A Raspberry Pi-based IDS that continuously monitors and protects the local network.

Both sensors generate security telemetry that is processed, classified, and visualized through a centralized dashboard, enabling real-time monitoring and defensive response.

# Architecture Overview

## 1. Attack Sources

The system is designed to observe genuine attack traffic originating from the Internet.

Typical attack sources include:

* Botnets
* SSH brute-force campaigns
* Automated vulnerability scanners
* Port scanners
* Malware operators
* Internet reconnaissance bots

These attackers interact with exposed honeypot services hosted in the cloud while the local IDS independently monitors activity within the protected LAN.

---

## 2. Threat Sources

The detection layer consists of two independent telemetry sources.

### ☁️ Cloud Threat Sources

AWS hosts multiple Internet-facing honeypot services that intentionally simulate vulnerable systems.

Current services include:

* Web Honeypot
* SSH Honeypot
* Telnet Honeypot

These services collect information such as:

* Brute-force attempts
* Port scanning activity
* Credential attacks
* Reconnaissance requests
* Malware download attempts
* Botnet behavior

This telemetry represents real-world attacks occurring on publicly exposed infrastructure.

---

### 🏠 Local Threat Sources

A Raspberry Pi functions as a lightweight Intrusion Detection System (IDS) within the local network.

It continuously monitors network traffic using packet inspection and behavioral analysis.

Current detection modules include:

* Port Scan Detection
* SSH/Telnet Brute Force Detection
* DNS Threat Detection
* Malware Activity Detection
* Network Census & Device Discovery

Unlike the cloud honeypots, the local IDS focuses on identifying suspicious activity targeting devices within the internal network.

---

# 3. Threat Analytics Engine

Telemetry generated from both cloud and local sensors is forwarded to the Threat Analytics Engine.

This component performs the following tasks:

* Event normalization
* Feature extraction
* Machine-learning-assisted classification
* Event correlation
* Confidence scoring
* Risk assessment

Behavioral heuristics are combined with lightweight machine learning models to reduce false positives and improve attack classification.

The output of this stage is a normalized security event containing:

* Attack type
* Source IP
* Confidence score
* Supporting evidence
* Environment (Cloud / Local)

---

# 4. Telemetry API

The Telemetry API acts as the central communication layer of the platform.

Built using Flask, it provides REST endpoints responsible for:

* Receiving security events
* Storing telemetry
* Serving dashboard queries
* Processing mitigation requests
* Synchronizing platform components

All telemetry is forwarded to the backend database before being consumed by the dashboard.

---

# 5. Security Dashboard

The platform includes a SOC-style dashboard built using Streamlit.

The dashboard provides two operational modes.

### 🌍 Global Threat Intelligence

Displays attacks collected by AWS honeypots, including:

* Global attack feed
* Attack history
* Threat categorization
* Country attribution
* Attacker leaderboard
* Risk intelligence

---

### 🏠 Local Network Defense

Displays telemetry generated by the Raspberry Pi IDS, including:

* Local attack history
* Connected devices
* Network status
* Device inventory
* Suspicious hosts
* Blocked devices
* Mitigation controls

This separation allows operators to distinguish between Internet-wide attacks and activity occurring within the protected network.

---

# 6. Secure Remote Access

The dashboard communicates securely with the backend using a Cloudflare Tunnel.

This enables secure remote management without exposing the Telemetry API directly to the public Internet.

---

# 7. Data Storage

Security telemetry is stored inside a lightweight SQLite database.

The database maintains information including:

* Attack logs
* Device inventory
* Known devices
* Blocked IPs
* Suspicious devices
* Historical telemetry

The centralized database enables efficient querying, historical analysis, and dashboard visualization.

---

# 8. Automated Mitigation

The platform supports active defensive response through a dedicated mitigation engine.

Authorized operators can issue response actions directly from the dashboard.

Supported actions include:

* Block IP
* Unblock IP
* Watchlist management
* Suspicious device tracking

Commands are validated before being enforced on the Raspberry Pi.

---

# 9. Firewall Enforcement

The mitigation engine applies defensive actions using Linux **iptables**.

When an operator selects **Block** on the dashboard, the following sequence occurs:

```text
Dashboard
        │
        ▼
Telemetry API
        │
        ▼
Mitigation Engine
        │
        ▼
iptables Rule Injection
        │
        ▼
Blocked Device
```

Firewall rules are dynamically inserted into the INPUT and FORWARD chains to prevent communication from malicious hosts.

The mitigation engine also maintains a persistent watchlist, allowing blocked devices to be tracked and managed over time.
